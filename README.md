# Synapse Research

Веб-приложение для исследований по научным и техническим документам. Команда загружает источники, находит фрагменты с цитатами и запускает исследования через агентов Synapse. История, решения по запросам согласования, итоговые ответы и созданные материалы доступны в одном рабочем пространстве.

Продукт предназначен для исследователей, инженеров и аналитиков. Тематика определяется выбранными документами и настройками workflow Synapse.

## Возможности

- **Документы** — загрузка, выбор корпуса, предварительный просмотр и скачивание первоисточников, удаление файлов.
- **Поиск фрагментов** — локальный поиск по выбранным документам с цитатой и указанием страницы, записи или другого места в источнике.
- **Исследования** — передача вопроса и выбранных файлов в workflow Synapse, отслеживание состояния и этапа выполнения.
- **Согласования** — просмотр данных запроса, комментарий и подтверждение либо отклонение непосредственно в карточке исследования.
- **История команды** — сохранённые запуски, фильтрация и возврат к ранее полученным результатам.
- **Результаты** — полный текст ответа, просмотр HTML-отчёта и скачивание созданных материалов.

Активные страницы: `/` и `/documents` — документы, `/researches` — история, `/researches/:id` — отдельное исследование. Остальные разделы временно недоступны в интерфейсе.

## Пользовательский сценарий

1. Загрузите документы в библиотеку.
2. Выберите источники и сформулируйте исследовательский вопрос.
3. Найдите фрагменты локально или запустите исследование в Synapse.
4. Если workflow запросит решение, проверьте данные и подтвердите либо отклоните запрос.
5. Откройте результат исследования и сохраните нужные материалы.

Локальный поиск выполняется без обращения к языковой модели. При запуске исследования выбранные файлы передаются в настроенный экземпляр Synapse. Найденная цитата и ответ агента требуют проверки специалистом перед использованием в научном или инженерном решении.

## Поддерживаемые документы

PDF с извлекаемым текстом, JSON/JSONL/NDJSON, CSV/TSV, XML, JATS/NXML, TEI, HTML, TXT/Markdown, RIS и BibTeX. Сканированные PDF без текстового слоя пока не поддерживаются: OCR не реализован.

Локальная библиотека и workflow Synapse могут поддерживать разные наборы форматов. Ошибка передачи неподдерживаемого файла показывается при запуске исследования. Обработка зависит от доступной памяти и диска; программных лимитов на размер загружаемого файла или объём извлечённого текста нет.

## Стек и структура

- **Frontend:** React 18, TypeScript, Vite, SCSS Modules.
- **Backend:** Python, FastAPI, Clean Architecture.
- **Хранение:** исходные файлы и индекс библиотеки на диске, история исследований и кеш материалов в SQLite.
- **Развёртывание:** Docker Compose, Caddy, GitHub Actions и GitHub Container Registry.

```text
frontend/           интерфейс документов и исследований
backend/app/        API, сценарии приложения, доменные правила и адаптеры
backend/tests/      проверки backend
deploy/             production Compose, Caddy и подготовка VPS
.github/workflows/  проверки, сборка образов и развёртывание
docs/ui-ux/         описание интерфейса и результаты его проверок
.agents/skills/     проектные инструкции для разработки
```

Frontend и backend запускаются независимо и взаимодействуют через REST API под `/api`. В разработке Vite перенаправляет `/api` на backend; на VPS маршрутизацией занимается Caddy.

## Локальный запуск

Нужны Docker с Compose и Node.js 22.

Создайте `.env` по образцу `.env.example`, если файла ещё нет. Для работы с Synapse заполните параметры подключения, затем запустите backend:

```bash
docker compose up --build -d backend
```

В другом терминале запустите frontend:

```bash
cd frontend
npm ci
npm run dev
```

Откройте [localhost:5173](http://localhost:5173). Проверка backend: [localhost:8091/api/health](http://localhost:8091/api/health).

Без настройки Synapse остаются доступны локальная библиотека документов и поиск фрагментов.

## Настройки Synapse

Все параметры приложения задаются через ENV. Полный пример — [`.env.example`](.env.example).

| Параметр | Назначение |
| --- | --- |
| `SYNAPSE_URL` | Адрес API экземпляра Synapse |
| `SYNAPSE_UI_URL` | Адрес интерфейса того же экземпляра для перехода к подробностям |
| `SYNAPSE_USER`, `SYNAPSE_PASSWORD` | Учётные данные API-пользователя |
| `SYNAPSE_WORKFLOW_ID` | UUID основного workflow; необходим для готовности интеграции |
| `SYNAPSE_DOCUMENT_WORKFLOW_ID` | UUID workflow исследования документов; при пустом значении используется основной workflow |
| `SYNAPSE_DOCUMENT_RUN_CONFIG_ID` | Необязательная конфигурация запуска; `agent-owned-models` сохраняет модели, выбранные агентами workflow |
| `SYNAPSE_APPROVAL_MODE` | Режим согласований; для ручных решений — `human` |
| `SYNAPSE_TIMEOUT` | Тайм-аут обращения к Synapse в секундах; пример настройки — `300` |

Нужны именно UUID workflow, а не их отображаемые названия. Вход в Synapse через браузер не передаёт учётные данные backend приложения. После изменения ENV пересоздайте backend-контейнер: обычный `restart` не применяет новые переменные контейнера.

## Доступ и хранение

`DOCUMENT_ACCESS_TOKEN` задаёт общий код команды для документов, исследований и истории. Интерфейс хранит введённый код в текущей вкладке браузера. При пустом значении доступ открыт, что допускается для локальной разработки. Отдельных пользовательских учётных записей и личных историй нет.

`DOCUMENT_ACCESS_CODE_COPY_ENABLED=false` отключает временную кнопку копирования кода доступа. Её включение предназначено только для временного стенда.

Локальный Compose сохраняет данные в `backend/data`. Production Compose монтирует постоянный том в `/service/var/documents`: там находятся библиотека, `researches.sqlite3` и кеш материалов. Резервная копия должна включать весь каталог документов вместе с базой истории. Удаление исходного документа сохраняет его название в истории, но не сохраняет оригинал файла в записи исследования.

История включает запуски, сделанные через приложение; старые проекты Synapse не импортируются. Состояние обновляется, пока открыта страница, либо по ручному запросу. Фонового опроса при закрытом интерфейсе нет.

## Основной API

| Маршрут | Назначение |
| --- | --- |
| `GET /api/health` | Проверка backend и наличия настроек Synapse |
| `GET /api/documents` | Список документов |
| `POST /api/documents` | Загрузка документа |
| `POST /api/documents/search` | Локальный поиск фрагментов |
| `POST /api/documents/research` | Запуск исследования по выбранным документам |
| `GET /api/researches` | История команды |
| `GET /api/researches/{id}` | Сохранённое исследование |
| `POST /api/researches/{id}/refresh` | Обновление состояния из Synapse |
| `POST /api/researches/{id}/approvals/{approval_id}` | Решение по запросу согласования |
| `GET /api/researches/{id}/files/{file_id}` | Скачивание материала исследования |

Запуск поддерживает `request_id` в формате UUID для защиты от повторного создания проекта. При неизвестном результате отправки приложение сохраняет состояние `start_unknown`: перед повторным запуском проверьте историю Synapse.

## Развёртывание и совместимость

Инструкции по единому `/opt/pav/.env`, VPS, GitHub Secrets и выпуску образов находятся в [`deploy/README.md`](deploy/README.md). Backend и frontend публикуются с одной версией — полным SHA коммита.

На существующем VPS сохранены каталог `/opt/pav` и имя Compose-проекта `pav-evidence-navigator`, чтобы использовать уже созданные тома и данные. Эти технические имена не являются названием продукта. Для совместимости также сохранены переменные `PAV_HTTP_TRACE_ENABLED`, `PAV_PORT` и прежние ключи браузерного хранилища.

В коде остаются серверные возможности анализа лабораторных опытов и демонстрационный корпус по поверхностно-активным веществам. Соответствующие разделы интерфейса отключены; демонстрационные записи не являются проверенной производственной базой. Исторические материалы в `docs/ui-ux` описывают в том числе прежние версии интерфейса.
