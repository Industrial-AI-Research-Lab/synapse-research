# Просмотр JSON и текстовых файлов внутри приложения

Дата исследования: 20.10.2026. Статус: просмотрщик реализован во всех пяти местах, компактные кнопки одобрены и применены. Проверки и ограничения — `document-preview-verification.md`.

## Запрос и подтверждённая граница

Пользователь вынужден сохранять JSON на устройство, чтобы прочитать содержимое. Нужно добавить просмотр исходного файла внутри текущего приложения рядом со скачиванием и использовать его во всех активных местах работы с файлами.

Пользователь уточнил: «Только JSON и текстовые форматы». PDF, изображения, Word и Excel не входят в это предложение. Текущее открытие PDF сохраняется. Визуальная основа — существующий Фолио: тёплый фон, оливковые действия, общие кнопки и иконки.

20.10.2026 пользователь подтвердил представление JSON: «Дерево + исходный текст». Преобразование JSON в читаемую статью без служебных полей не требуется. Выбор представления зафиксирован; реализация приложения в рамках исследования не выполнялась.

## Минимальное решение

Один общий компонент `DocumentPreview` рядом с остальными общими компонентами, с собственным SCSS-модулем. Экран передаёт имя и функцию получения исходного Blob либо локальный File из очереди. Каждый экран сохраняет своё получение данных; новый глобальный store, новый серверный маршрут и универсальный редактор не нужны.

В `IconRenderer` добавить `view` с глазом и SVG в существующем стиле. Использовать общий Button: компактная круглая кнопка 32 px / 44 px на сенсорном устройстве, иконка 16 px, отступ фокуса 3 px. Подпись — «Просмотреть [имя файла]». Скачивание остаётся отдельным действием. Имя файла рядом с чекбоксом в библиотеке продолжает выбирать документ для исследования.

Окно открывается поверх текущей страницы. В компактной шапке — только имя файла и крестик. Для JSON слева — «Исходный текст», выбранный при открытии, справа — «Структура»; для остальных файлов — текст без панели переключателей. Копирование всего файла удалено, скачивание оригинала сохранено. Нумерация и счётчики дерева не добавляются. Escape и крестик закрывают окно, фокус возвращается на нажатую кнопку. На телефоне окно занимает доступную ширину, длинные имена переносятся, текст и панель действий не выходят за экран. Используется нативный dialog с управлением фокусом по существующему образцу окна загрузки.

| Место подключения | Текущий код | Поведение |
|---|---|---|
| Библиотека документов | `DocumentsWorkspace.tsx:1499` | Глаз рядом со скачиванием и удалением |

| Очередь перед загрузкой | `DocumentsWorkspace.tsx:1889` | Просмотр локального File до отправки; выбор и очередь сохраняются |

При просмотре из очереди нужно сохранить очередь и вернуть фокус в окно загрузки. Реализация не должна случайно закрывать его или запускать загрузку.

Недоступные старые разделы не восстанавливаются ради просмотрщика: активные маршруты определены в `frontend/src/app/App.tsx:55`. Существующий HTML-отчёт исследования сохраняет отдельное безопасное представление. Предложение не обещает переход к точной записи JSON по номеру поискового фрагмента: индексация может менять представление текста (`multiformat_text_extractor.py:167`).

## Форматы

| Формат | Представление |
|---|---|
| JSON | Дерево для объектов/массивов, исходный текст всегда доступен; JSON-примитивы показываются текстом |
| JSONL, NDJSON | Исходный текст; при добавлении структуры разбирать каждую непустую строку отдельно, не применять JSON.parse ко всему файлу |
| TXT, MD | Текст с сохранёнными переносами; Markdown не требует отдельного рендерера в этой версии |
| CSV, TSV | Текст с разделителями; таблица не обязательна для решения задачи |
| XML, TEI, JATS, NXML | Текст разметки |
| HTML, HTM | Текст разметки, без исполнения кода и загрузки внешних ресурсов |
| RIS, BIB | Текст библиографических записей |

Для прочих текстовых материалов исследования допустим простой текст по согласованному списку MIME и расширений. Не пытаться читать неизвестный бинарный файл как текст. Добавление просмотра не расширяет список разрешённых загрузок.

## Состояния и проверка реализации

- Загрузка: окно видно сразу, есть понятное ожидание и возможность закрыть его. Запоздалый ответ после закрытия или переключения не открывает старый файл заново.
- Пустой файл: «Файл пуст». Невалидный JSON: сообщение об ошибке разбора и исходный текст вместо сломанного окна.
- 401/403, удалённый документ, ошибка сети: понятное сообщение; повтор по существующему механизму доступа.
- Декодирование должно учитывать кодировки, которые уже принимает сервер; одного Blob.text для Windows-1251 недостаточно.
- Исходный текст и скачивание используют оригинальные данные, а не JSON.stringify разобранного объекта. Большие целые числа могут терять точность при JSON.parse; это нужно учесть до разрешения дерева для таких файлов.
- Не раскрывать все узлы автоматически. Большие и глубоко вложенные JSON требуют ограничения представления и понятного перехода к исходному тексту. Численный порог выбрать после проверки реальных размеров; производительность библиотеки на пользовательских файлах не измерялась.
- JSONL не путать с обычным JSON. XML/HTML показывать как текст React, без dangerouslySetInnerHTML. Материалы не передаются сторонним просмотрщикам.
- Закрытие освобождает состояние файла. URL скачивания освобождается таймером. Исходный текст можно выделить вручную; отдельного действия копирования нет.
- При реализации проверить все пять точек входа, Escape/возврат фокуса, русский текст, длинные имена, узкий экран, ошибки и невалидный JSON; затем lint/build frontend.

Оценка пропорциональности: только просмотр текста — ориентировочно 150–250 строк общего компонента и подключений; дерево, состояния и пять точек входа — ориентировочно 300–500 строк. Это предварительная оценка объёма, не замер. Конвертация документов на сервере, Monaco и универсальная платформа просмотра для этой задачи избыточны.

ADR не создаётся: выбор лёгкого клиентского представления обратим и не меняет доменную модель либо API. Термины исходного файла и материала исследования уточнены в CONTEXT.md.
