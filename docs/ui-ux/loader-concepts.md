# Лоадер Synapse Research: варианты для обсуждения

Дата: 16.10.2026. Статус: пользователь выбрал «Сборку ответа» и явно разрешил заменить качалку во всём приложении. Общий компонент обновлён.

## Контекст и границы

PRODUCT.md и DESIGN.md задают исследование по выбранным документам, светлую палитру «Фолио», оливковый акцент, Lora и Inter. Новый лоадер наследует эти решения.

До замены `frontend/src/components/ui/Loader/Loader.tsx` показывал нефтяную качалку с подписью по умолчанию «Поднимаем данные из пласта…». Сохранены варианты page, inline и overlay. В `frontend/src/app/documents/DocumentsWorkspace.tsx` поиск использует подпись «Ищем фрагменты в выбранных документах…». Исследование и поиск фрагментов — разные понятия согласно CONTEXT.md; оформление ожидания запроса не заменяет состояние исследования.

## Три предложения

1. **Связь источников** — несколько устойчивых узлов, короткие импульсы по связям и спокойное изменение центрального узла. Рекомендация для общей замены: соответствует названию Synapse и сохраняет смысл при разных запросах. Ограничение: метафора абстрактнее документа.
2. **Чтение документа** — стопка листов и мягкая полоса, проходящая по строкам. Самая понятная метафора поиска по документам, хорошо сочетается с «Фолио». Ограничение: менее характерна для бренда; не всякая загрузка означает чтение содержимого.
3. **Сборка ответа** — фрагменты слева, движущийся сигнал и складывающиеся строки справа. Выражает переход от источников к результату. Ограничение: для обычной загрузки списка слишком конкретна и может восприниматься как обещание генерации ответа.

Во всех набросках одна и та же реальная подпись поиска: сравнивается движение, а не текст. Графика символическая; положение элементов не обозначает измеренный прогресс или действительные стадии работы агентов.

## UX-основания

- [NN/g: Progress Indicators](https://www.nngroup.com/articles/progress-indicators/) — понятная обратная связь при ожидании; неопределённая анимация, когда объём оставшейся работы неизвестен.
- [NN/g: Designing for Long Waits and Interruptions](https://www.nngroup.com/articles/designing-for-waits-and-interruptions/) — для долгих операций полезнее сведения о реальном состоянии и возможность продолжать другую работу.

Предложения к реализации после выбора: не вводить выдуманные проценты или стадии, сохранять подпись текущего запроса, показывать результат сразу по готовности, учитывать уменьшение движения, сохранять доступное объявление состояния. Длительное исследование продолжает использовать свои реальные состояния.

## Согласованное решение

Пользователь выбрал «Сборку ответа» как одну общую анимацию, а не набор разных лоадеров. Явное разрешение: «Да, апрув, заменяем качалку на “Сборку ответа” во всём приложении». Подпись по умолчанию — «Загружаем данные…». Подписи вызывающих экранов сохранены. ADR не нужен: локальная визуальная замена легко обратима; проектные термины не меняются.

## Проверка реализации

Общий React-компонент проверен в браузере с реальными стилями приложения для inline, page и overlay на ширинах 1280 и 320 px. Графика помещается, горизонтального переполнения при обычном размере текста нет. Длинная непрерывная подпись переносится; пустая и пробельная подписи сохраняют прежнее поведение; строка с HTML выводится как текст. При prefers-reduced-motion движение отключено, лист и строки остаются видимыми. Сохранены role=status, aria-live=polite и скрытие декоративной графики от скринридера.

Проверки npm run lint и npm run build прошли. Детектор impeccable не выдал замечаний. Полные серверные сценарии и реальная длительность исследований не проверялись: изменение ограничено отображением общего компонента.

При удвоенном базовом размере шрифта сам лоадер также помещается в контейнер 320 px. Общая страница при таком размере имеет прежнее ограничение body min-width:20rem (`frontend/src/styles/global.scss:22`); изменение общих правил масштабирования не входило в эту замену.
