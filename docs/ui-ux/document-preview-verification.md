## Ограничения

### Высота окна — уточнение 20.10.2026

Пользователь сообщил, что на высоком экране длинный документ растягивает окно почти на всю высоту. Причина: прежний максимум вычислялся только от viewport (`100dvh - 2rem`). Общий просмотрщик теперь использует одну переменную `--preview-max-height: min(48rem, 80dvh)` и согласованный предел внутренней компоновки с учётом границы 2 px. Минимальная высота также ограничена этой переменной.

Это выбор размеров для нашего интерфейса. Общий подход — ограничить высоту модального окна, прокручивать body и сохранять header/footer на месте — соответствует Carbon: https://www.carbondesignsystem.com/building-blocks/core/patterns/dialogs . Carbon не задаёт выбранные нами 768 px как универсальную норму.

Проверка на длинном тестовом JSON в собранном приложении:

| Высота окна браузера | Высота просмотрщика | Отступ сверху/снизу |
|---|---|---|
| 700 px | 560 px | 70 px |
| 1000 px | 768 px | 116 px |
| 1600 px | 768 px | 416 px |
| 820 px при ширине 360 px | 656 px | 82 px |

Для всех измерений внешняя область окна не прокручивается и не переполняется по горизонтали; прокручивается содержимое. Режим исходного текста также ограничен 768 px на высоком экране. Короткий JSON занимает 450 px. Временные настройки viewport восстановлены. Файл получается целиком существующим API. При размере больше 5 MiB показывается только начало с явным сообщением, скачивание сохраняет весь оригинал. Это ограничение отображения, не сетевого объёма.

Поддержаны UTF-8, UTF-8 BOM, UTF-16 BOM LE/BE и Windows-1251. UTF-16 без BOM отдельно не определяется. NUL вызывает сообщение о двоичных данных.
