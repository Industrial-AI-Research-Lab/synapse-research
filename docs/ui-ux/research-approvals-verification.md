# Согласования исследования — 19.10.2026

Реализованы пять утверждённых состояний в существующем мире «Фолио». Понятное представление дополняет открытый полный блок «Данные для решения» с JSON, копированием и прежней прокруткой; данные не сокращаются и не переписываются при отправке решения.

## Представление

| Этап | Подача |
| --- | --- |
| approve_manifest | Русское пояснение, вопрос и документы из снимка конкретного согласования. Текущий список источников исследования не подменяет снимок. |
| approve_ontology | Версия, охват, число прочитанных фрагментов, документы, имена материалов и исходные ограничения. |
| approve_calculators с предложениями | Названия, формулы, вложенные входные данные, единицы, основания и ограничения. Известные названия полей переведены; неизвестные поля сохранены. |
| approve_calculators с явным proposals: [] | Причины из gaps и limitations; основное действие «Продолжить без калькуляторов». Отсутствие или неправильная форма proposals не считается пустым списком. |
| publish_report | Переход к единственному общему блоку результата с HTML в прежнем sandbox или текстовым ответом; при отсутствии отчёта — явное пояснение. Исходные данные публикации доступны полностью. |

Выбор текста использует gate_node_id, а не заголовок или английскую фразу. Неизвестный этап получает нейтральный русский заголовок и сохраняет исходное сообщение. Поддержано сохранённое описание в details, если expected_data отсутствует, и выход агента из context_snapshot.custom.

Название «На доработку» используется только когда next_steps.reject явно ведёт в фазу refine_target_node_id. Это существующее отклонение с комментарием и возвратом по графу, а не новая операция revise. Если переход неизвестен, остаётся «Отклонить»; завершение запуска объявляется только при next_steps.reject.type=end.

API, защита expected_data, обновление состояния, блокировка кнопок во время отправки / синхронизации и сохранение комментария при ошибке сохранены. Нового запроса к Synapse для форматирования нет.

## Размещение и стиль

ApprovalSummary.tsx и approvalSummary.module.scss находятся рядом с ResearchDetail; чистые функции подготовки — в approvalPresentation.ts. Экран продолжает владеть запросами, комментарием, отправкой, ошибками и уведомлениями. Используются прежние Lora, Inter, токены, миксины типографики и общие Button, Field, Textarea, ApprovalDetails. Местоположение ToastViewport не менялось.

## Границы

Реальные подтверждения / отклонения не отправлялись; workflow до конца заново не запускался. Положительные предложения калькуляторов проверены на синтетических данных, поскольку проверенная реальная история содержала пустой список. HTML-предпросмотр использует прежнюю изоляцию; ветвь HTML проверена по коду и сборкой, публикация в браузере проверена с текстовым результатом. Отдельного прогона скринридером и на физическом сенсорном устройстве нет. Содержательные сообщения агента сохраняются на исходном языке; новый словарь переводит интерфейс, но не переписывает выводы агента.

Снимки реального экрана и мобильной проверки сохранены в каталоге визуализаций текущего чата; временные ответы и журнал изолированного сервера находятся в исключённой из Git области .impeccable/review/approval-states.

## Уточнение после проверки пользователем

Повторяющиеся вопрос и документы удалены из читаемого блока согласования. Имена документов сравниваются как отображаемый набор с сохранением количества повторений; порядок и разные ID между локальным корпусом и загрузкой Synapse не создают повторный список. Отличающийся вопрос или состав выводится отдельно с явной подписью, отсутствие снимка не объявляется совпадением. В структуре данных совпадающий manifest также не дублируется.

Имя калькулятора больше не повторяется сразу после заголовка. Материалы, уже присутствующие в «Созданных материалах», доступны по якорной ссылке; незарегистрированные материалы сохраняют имена в согласовании. Отчёт показан один раз в «Результате исследования», согласование публикации ссылается на него. Полный JSON по просьбе пользователя оставлен полностью.

Синий цвет, ошибочно добавленный при интерпретации замечания пользователя, убран. Заголовки чернильные; переходы и раскрытие данных оливковые через существующие токены. В браузере подтверждены rgb(12, 20, 37) для заголовка и rgb(74, 98, 72) для раскрытия во всех пяти состояниях. Дополнительно проверены отдельно отличающийся вопрос, отличающийся список документов и переход к уже показанным материалам; в публикации проверочный текст отчёта присутствует ровно один раз.
