# Загрузка документов из поиска

Дата: 15.10.2026.
Статус: сценарий подтверждён пользователем с добавлением Toast-уведомлений; реализован в интерфейсе.

## Задача и направление

Пользователь работает с источниками для поиска фрагментов или исследования. Добавление файлов должно быть доступно рядом со списком документов без перехода в отдельную вкладку.

Направление с учётом уточнения пользователя: сохранить внутренний переключатель «Документы / Поиск» для дальнейшего расширения другими вкладками. «Поиск» остаётся активной вкладкой, «Документы» отображается в состоянии disabled и не открывает прежний экран загрузки. Загрузка открывается в диалоге по кнопке «Добавить документы». Верхний раздел «Работа с документами» сохраняется. Существующие оформление и возможности загрузки служат основой.

## Что подтверждено текущей реализацией

Источник: `frontend/src/app/documents/DocumentsWorkspace.tsx`.

- Вкладка «Документы» содержит выбор файлов, очередь загрузки и сводку с переходом к поиску; выбор и удаление загруженных документов находятся в поиске.
- Можно выбрать несколько файлов, увидеть имена и размеры и убрать отдельные файлы из очереди перед отправкой.
- Файлы отправляются последовательно. Успешно добавленные документы сохраняются даже при ошибке других файлов; для повторной попытки в очереди остаются неудачные файлы.
- Загруженные документы добавляются в начало списка. Прежний выбор сохраняется, новые документы включаются в выбор в пределах ограничения 50 документов.
- Если документов ещё нет, приложение сейчас открывает вкладку загрузки автоматически.

## Рекомендации к переносу

- Показывать экран поиска с сохранённым переключателем вкладок. При пустой библиотеке показывать приглашение добавить документы с кнопкой открытия того же диалога.
- В диалог переносить форму и очередь файлов. Сводка «Документы готовы к поиску» и переход «Перейти к поиску» становятся избыточными: список находится под диалогом.
- Сохранять вопрос, отмеченные документы и уже показанные результаты при открытии и закрытии загрузки. Обновление списка не запускает поиск автоматически.
- Ошибки загрузки показывать внутри диалога рядом с очередью. При частичном успехе оставлять неудачные файлы и возможность повторить отправку.
- Делать диалог доступным: видимый заголовок и кнопка закрытия, перевод фокуса внутрь, удержание Tab/Shift+Tab внутри, недоступный для взаимодействия фон, возврат фокуса после закрытия. Базовое поведение Escape — закрытие. Источник: [WAI-ARIA APG, Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).
- На небольшом экране диалог может занимать почти весь экран; длинная очередь должна прокручиваться, сохраняя доступ к действиям.

Это локальное изменение интерфейса. Смена API, форматов файлов или организации серверной обработки для него не требуется. Отдельный ADR не нужен: решение легко обратимо.

## Согласованные решения

- Внутренние вкладки «Документы / Поиск» сохраняются для будущего расширения. «Поиск» активна, «Документы» недоступна для переключения (disabled).
- После успешной загрузки всех выбранных файлов диалог автоматически закрывается. Подтверждение появляется рядом с обновлённым списком документов на экране поиска.
- При частичном успехе открытый диалог остаётся открытым: успешно загруженные документы уже добавлены, неудачные файлы остаются в очереди для повторной попытки.
- Пользователь может закрыть диалог во время загрузки; отправка файлов продолжается в фоне. На экране поиска остаётся состояние загрузки, повторное нажатие «Добавить документы» открывает ту же очередь. Если ошибка произошла после закрытия, на экране поиска появляется сообщение с возможностью вернуться к очереди; диалог не открывается самопроизвольно.
- Продолжение загрузки обеспечивается при закрытии диалога на текущем экране. Продолжение при переходе в другие разделы приложения, обновлении страницы или закрытии браузера в этот сценарий не входит.

## Toast-уведомления

- При начале отправки появляется информационное уведомление «Загрузка началась». На экране поиска и внутри открытого диалога отображается число обработанных файлов.
- При закрытии диалога во время отправки появляется информационное уведомление «Загрузка продолжается». При закрытии до отправки выбранные файлы сохраняются в очереди, о чём также сообщается пользователю.
- При полном успехе появляется уведомление «Документы загружены» с результатом добавления. При частичном успехе уведомление показывает число добавленных файлов и ошибки остальных.
- Ошибка сервера или сети отображается как Toast независимо от того, открыт ли диалог. Уведомление об ошибке сохраняется до закрытия пользователем или изменения очереди; из закрытого диалога можно вернуться к очереди кнопкой «Открыть загрузку» в уведомлении.
- В открытом диалоге Toast находится внутри окна, чтобы оставаться доступным при заблокированном фоне. После закрытия уведомления отображаются в существующем стеке Toast на странице.
- Уведомления о результате успешной загрузки и сохранении очереди закрываются автоматически через пять секунд; существующие паузы при наведении, фокусе и скрытой странице сохраняются. Во время отправки уведомление не исчезает автоматически.

## Сохранение текущего поведения

- Закрытие и повторное открытие диалога сохраняют выбранные для отправки файлы, включая очередь после ошибки. Уже добавленные документы повторно не отправляются.
- Ранее отмеченные документы сохраняются. Новые документы автоматически включаются в выбор на свободные места до ограничения 50 документов. Загрузка в библиотеку сама по себе этим ограничением не ограничена.
- Во время отправки нельзя повторно запустить ту же очередь, изменить набор отправляемых файлов или убрать файл из него. Закрыть диалог и продолжить работу на текущем экране можно.
- Форматы файлов, последовательная отправка, работа с кодом доступа команды, поиск, исследования и удаление загруженных документов сохраняют существующие правила.

## Уточнение обратной связи

Если добавленные документы не вошли в выбор из-за ограничения 50 документов, Toast явно сообщает количество невыбранных документов. Подтверждение загрузки не должно создавать впечатление, что все новые документы обязательно участвуют в следующем поиске.

## Проверка готового сценария

- Пустая библиотека: активен поиск, вкладка «Документы» disabled, кнопка добавления открывает доступный с клавиатуры диалог.
- Полный успех: диалог закрывается, список и сообщение об успехе обновляются; вопрос и прежние результаты сохраняются.
- Частичный или полный отказ: успешно добавленные документы доступны, очередь содержит только неудачные файлы с сообщением об ошибке и возможностью повторить загрузку.
- Закрытие во время отправки: на странице виден статус; повторное открытие возвращает к той же очереди без повторной отправки. Результат загрузки сообщается также при закрытом диалоге.
- Закрытие до отправки: при повторном открытии выбранные файлы сохранены. Очередь с длинными именами и большим количеством файлов остаётся доступной на узком экране.
- Достигнут выбор из 50 документов: новые файлы добавляются в библиотеку без вытеснения прежнего выбора, пользователь видит, что часть файлов не выбрана.

## Результат проверки реализации

- Проверки ESLint, TypeScript и production-сборка прошли. Детектор Impeccable не обнаружил замечаний в изменённых файлах.
- Браузерные проверки прошли на тестовых ответах API: полный и частичный успех, ошибки HTTP 413/500/503 и обрыв сети, повторная отправка только неудачных файлов, сохранение вопроса и результатов, удержание Tab/Shift+Tab и возврат фокуса после закрытия.
- Проверены сохранение выбора при завершении загрузки, ограничение 50 документов и совпадающие идентификаторы в ответах на загрузку одинаковых файлов. Совпадающие документы не дублируются в списке или счётчике невыбранных документов.
- Проверена адаптивность на ширинах 320, 375 и 1440 пикселей, включая очередь из 18 файлов с длинными именами. В браузерном прогоне ошибок выполнения не было.
- Поддержка остальных форматов, помимо TXT, CSV и отказа на повреждённом PDF, отдельно не проверялась. Продолжение загрузки после ухода с экрана не входит в согласованный сценарий.

## Проверка на реальных файлах

15.10.2026 выполнен отдельный прогон через настоящий локальный API PAV без подмены ответов загрузки.

- TXT размером 146 000 байт отправлялся с ограничением скорости в тестовом браузере. Сразу после закрытия диалога документ ещё отсутствовал на сервере, а HTTP-запрос оставался незавершённым. Через 5,5 секунды после закрытия сервер вернул HTTP 201, документ появился в библиотеке и Toast сообщил об успехе.
- Повреждённый PDF размером 77 009 байт отправлен с закрытием диалога до ответа. Сервер вернул HTTP 422 «Не удалось безопасно извлечь текст из PDF.». Toast показал ошибку, сохранился дольше пяти секунд и позволил открыть очередь с неудачным файлом.
- Смешанная очередь из настоящего CSV размером 27 334 байта и повреждённого PDF дала HTTP 201 и 422. Toast показал «Добавлено файлов: 1 из 2»; CSV сохранился, в очереди остался только PDF.
- Исследования не запускались. В тестовом браузере были заблокированы внешние адреса и любые API-запросы, кроме локальной загрузки и чтения списка документов и локальной конфигурации. Попыток обращения к запрещённым адресам не зарегистрировано. Локальный GET `/api/synapse/config` читает настройки PAV и не обращается в Synapse.
- Созданные для проверки документы удалены из локальной библиотеки. Набор из 13 исходных документов восстановлен и сверён по идентификаторам. Ошибок выполнения в браузере не было.
