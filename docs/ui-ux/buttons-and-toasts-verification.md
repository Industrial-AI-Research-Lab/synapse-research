# Кнопки и тосты — внедрение и самопроверка

16.10.2026. Пользователь подтвердил совместное внедрение показанных макетов тостов и состояний кнопок. Изменены только frontend и описание дизайна. Серверные маршруты, данные и код Synapse не менялись.

## Область изменения

Общие Button, Toast, новые Spinner и ToastViewport; mixin/global/palette; документы, история, карточка исследования, доступ к истории, навигация и строка Synapse. Использован существующий компонент уведомления: дополнительная библиотека не нужна. При исследовании неизвестного запуска клиент сохраняет HTTP-статус в DocumentApiError; сигнатуры REST не изменены.

Сравнение выполнено с копией файлов перед началом этой реализации, а не со всем незакоммиченным diff репозитория. Предыдущие изменения пользователя сохранены. Копия и diff находятся в каталоге проверки, указанном ниже.

## Pre-ship 2. Предположения о дефектах

1. `Toast.tsx:105`: два скачивания подряд имеют одинаковый заголовок. Если исключить description из срока показа, новый файл закроется по таймеру старого. Исправлено через lifetimeKey без progress-описания во время выполнения. C: новый файл получает полный срок; новый результат не закрывается старым callback.
2. `documentsWorkspace.module.scss:611`: селектор `.uploadActions span` перекрашивает новые вложенные подписи Button. Сужен до непосредственного дочернего пояснения. UI проверяет, что busy-подпись белая; визуально подтверждено.
3. `Toast.tsx:127`: вернуть фокус к закрытому диалогу нельзя. Проверяются connected, видимость, disabled и принадлежность текущему диалогу; C проверяет возврат внутри открытого окна.

## Pre-ship 3. Дополнительная неудобная проверка

Закрыть тост, затем до конца его 120ms выхода получить новый успешный результат с тем же заголовком и другим файлом. Новый результат остаётся. Отдельно проверены 15s ожидания ошибки, 7s keyboard-focus и смена видимости вкладки управляемым событием.

## Pre-ship 4. Проверка между чтением и действием

| Операция | Условие и границы |
| --- | --- |
| Закрытие Toast | timeout-ref записывается синхронно до выхода из события; повторный close игнорируется. При новом lifetime cleanup отменяет старый timeout. C подтверждает гонку старого закрытия/нового файла |
| Скачивание двух типов в ResearchDetail | Общий isDownloadingRef устанавливается до await и освобождается в finally. Соседние кнопки disabled; UI подтверждает запрет |
| Upload | Ранее существовавший isUploadInFlightRef защищает последовательную очередь. Тосты не добавляют новых запросов и не отменяют её |
| Search/start/delete/copy | Native disabled устанавливается React при событии; handler проверяет состояние. Это защита UI, не распределённая блокировка и не серверная идемпотентность. Программные вызовы из внешнего JS вне пользовательского пути не заявлены как защищённые транзакции |
| Неизвестный старт | Клиент на текущем экране блокирует следующий запуск после uncertain-ответа; история остаётся способом проверки. Перезагрузка обходит локальный флаг; серверная защита от повторов этой работой не расширяется |
| Файлы и решения | Success публикуется только после завершения await. При ошибке комментарий/вопрос/очередь не очищаются. Прежняя серверная проверка решения сохраняется |

Новых DB-записей или изменений серверных транзакций нет.

## Pre-ship 5. Вызовы, соседние ветви и реальное подключение

App.tsx импортирует DocumentsWorkspace, ResearchHistory, ResearchDetail; все используют изменённый Button. DocumentsWorkspace использует Toast для загрузки, удаления и вспомогательного результата. ResearchDetail использует тот же Toast и ToastViewport. Spinner импортирован Button, Toast и документами. SynapseStatus из App также использует Button для повтора. Это те же production-imports, которые открывает Vite; отдельная тестовая копия компонентов не подменялась.

Просмотрены все импорты Button/Toast и применения mixin.control в frontend/src (279 совпадений общей поиска). Старые отключённые экраны продолжают компилироваться, их предметные workflow не включены заново. DocumentApiError остаётся экземпляром Error: остальные catch, использующие error.message, совместимы. HTTP payload и маршруты прежние. Связанные форматы документов, фильтры истории и оба типа исследования сохранены. Blob URL по-прежнему отзываются; новые timeout и listener очищаются на unmount. Countdown держит актуальный callback через ref.
