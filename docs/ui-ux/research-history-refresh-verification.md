# Иконка обновления истории — 16.10.2026

В существующую кнопку добавлена иконка reload через IconRenderer. Иконка слева обозначает действие; кнопка остаётся справа в заголовке, на узком экране — под описанием. Размер иконки 16px. Во время запроса вращение привязано к aria-busy; при prefers-reduced-motion движение отключено. Декоративная иконка скрыта от скринридера. Предыдущие незакоммиченные изменения сохранены; область проверки — разница с копиями файлов перед этой задачей.

Проверки: npm run lint, npm run build и Impeccable detect прошли. В Edge на реальных данных проверены ширины 1370 и 390px: кнопка соответственно 190.25 × 44.5 и 181.44 × 44px; иконка 16px, при 390px ширина документа 390px. Enter запускает обновление, после запроса доступна прежняя подпись. Ошибок в журнале браузера нет. Снимок сохранён в каталоге визуализаций текущего чата как research-history-refresh.png.

## Самопроверка перед завершением

1. Входы ResearchHistory: isRefreshing=false — подпись «Обновить историю», кнопка доступна; true — «Обновляем…», disabled и aria-busy, вращение только при no-preference. При отсутствии данных сохраняется Loader; при пустом массиве — пустая история; при непустом — фильтры и строки; при отсутствии совпадений — сообщение фильтра; при 401 — ResearchAccess; прочая ошибка — alert. Внутри строк сохранены ветви approvalCount и syncError. Эти ветви проверены чтением текущей разметки; непустой список проверен в браузере. Логика запросов и фильтров не менялась.
2. Предположение о дефекте: SVG в ResearchHistory.tsx:152 может растянуть кнопку из-за width/height=100%. Опровергнуто фиксированным контейнером в researchHistory.module.scss:35 и измерением 16 × 16px. Иконка не добавляет второе доступное имя благодаря aria-hidden на контейнере.
3. Неудобная проверка: ширина 390px и Enter. Кнопка полностью видна, горизонтального переполнения нет, после запроса кнопка снова доступна. Постоянные тесты для локального визуального изменения не добавлялись.
4. Атомарность: новых read→validate→write и внешних эффектов нет. disabled и aria-busy используют одно существующее состояние; защита isLoadingRef и запросы не изменены.
