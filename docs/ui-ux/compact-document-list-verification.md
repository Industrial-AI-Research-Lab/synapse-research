Реализован утверждённый макет в DocumentsWorkspace.tsx и соседнем documentsWorkspace.module.scss. API и обработчики выбора, скачивания и удаления не менялись.

## Проверки

- `npm run lint`, `npm run build`, `git diff --check` — успешно.
- Impeccable detect: замечаний нет.
- Chromium/Edge, реальная страница приложения, подставленные ответы API: 1440, 1024, 360 и 320 px. Горизонтального переполнения нет.
- На 1440/1024 px: строка 74 px, кнопки 32 px; на 360 px с сенсорным вводом: строка 98 px, кнопки 44 px. На 320 px метаданные переносятся, высота строки естественная.
- На всех ширинах: иконка файла 32 px, зазор до текста 8 px, радиус чекбокса 4 px, cursor pointer, насыщенность формата 600. Кнопки выровнены в одной колонке: открытие/скачивание сверху, удаление снизу.
- Проверены выбор чекбокса мышью, переключение пробелом, выбор нажатием на название, состояние загрузки и ошибка скачивания, открытие подтверждения удаления. Удаление настоящих документов не выполнялось.
- На компьютере проверен красный цвет удаления при наведении. Длинное название PDF обрезается многоточием, имя остаётся в title, действие остаётся «Открыть PDF».

## Pre-ship

### 1. Входные состояния

Изменена только разметка строк внутри DocumentsWorkspace и локальные стили; сигнатуры, контракты данных и обработчики сохранены.

| Состояние | Поведение | Доказательство |
|---|---|---|
| JSONL, CSV, MD | Иконка скачивания без видимой подписи | Браузерные проверки списка |
| PDF с длинным кириллическим именем | Иконка открытия; сокращённое название; полное имя в title | Браузер и существующий getDocumentFileAction |
| Чекбокс выбран / снят | Заливка и галочка / только граница | Мышь, Space и label в браузере |
| Скачивание выполняется | Spinner, aria-busy, доступное название «Скачиваем…», блокировка повторного запуска | Проверка с задержанным ответом |
| Скачивание завершилось ошибкой | Кнопка возвращается в исходное состояние, видна ошибка | Подставленный HTTP 500 |
| Пустой список / ошибка первоначальной загрузки | Существующие отдельные ветки экрана | Проверка исходного кода: изменённая строка находится только внутри documents.map |
| Узкая ширина / сенсорный ввод | Кнопки остаются справа; метаданные переносятся; область кнопок 44 px | 320 и 360 px |

### 2. Предположение о возможной ошибке

Старое правило контейнера переносило кнопки под названием при узкой колонке; оно удалено. Проверена постоянная вертикальная колонка действий на четырёх ширинах. Второй риск — невидимый loadingLabel общей кнопки расширял бы колонку; видимый loadingLabel удалён из этого экземпляра, доступное название состояния сохранено. Дополнительно исправлен приоритет hover/focus/active удаления: красная подсветка перекрывает общие стили кнопок.

### 3. Неудобный сценарий

На 320 px с сенсорным вводом проверены длинное имя, перенос метаданных, переключение пробелом и ошибка скачивания. Переполнения и наложения действий нет.

### 4. Атомарность

Новых последовательностей чтение → проверка → запись и внешних операций нет. Существующие handleOpenSource и подтверждение удаления сохранены. Проверки выполнялись с подставленными ответами; реальные документы не изменялись.

### 5. Вызывающие места и общие компоненты

Общие стили sourceLink отделены от компактной кнопки и сохранены. Другие использования getDocumentFileAction и handleOpenSource не менялись. Типы, внешние контракты и потоковые примитивы не менялись; проверка совместимости таких изменений неприменима. Экран подключён в App.tsx для `/` и `/documents`; браузерные проверки выполнялись на `/documents`.
