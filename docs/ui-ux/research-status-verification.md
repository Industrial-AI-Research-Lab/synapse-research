# Единый блок состояния: проверка 19.10.2026

Перенесён утверждённый вариант «Текстовое действие». Финальные уточнения: кнопка не подчёркнута ни в покое, ни при наведении, ни при запросе; зазор значка и текста 0.25rem; стрелка возврата центрирована. Порядок: статус, этап, проверка, причина остановки. REST-запросы и период автопроверки не изменялись.

## Проверки

- `npm run lint`, `npm run build`, `git diff --check` прошли.
- Impeccable detect по пяти изменённым исходным файлам вернул пустой список.
- Edge headless, реальные React-компоненты и Vite, подменённые ответы API. Серверные исследования не запускались и не изменялись.
- Снимки 1366×1000 и 390×1000 просмотрены; дополнительно проверено отсутствие горизонтального переполнения при 320 px и длинном названии.
- Проверены 20 значений статуса, пустые источники, отсутствие projectId, checkedAt=null, ошибка синхронизации, HTTP 503 при проверке, индикатор запроса и disabled.
- Цвета вычисленных стилей: ошибка #ac382d, причина #fbece8, действие #4a6248. Зазор времени и кнопки 8px, значка и текста 4px. У кнопки нет подчёркивания, включая hover и busy. Центры стрелки и ссылки совпадают с точностью до 1px.
- Два импульса статуса, вращение при запросе, отключение обоих эффектов при reduced motion. Капсула ошибки в истории сохраняет radius=999px.

### 2. Предположения о дефектах

Подозрение: более специфичный селектор пульсации ошибки перебьёт reduced-motion в researchStatus.module.scss. Браузер подтвердил проблему; media-селектор усилен до `.summary[data-status] .symbol::after`, повторная проверка прошла.

Подозрение: новый summary-вид случайно изменит капсулы в истории. Проверены оба потребителя: ResearchDetail явно передаёт variant=summary, ResearchHistory не передаёт вариант и сохраняет badge. Проверено в браузере.

### 3. Неудобная проверка

Во время незавершённого запроса включено reduced motion: кнопка остаётся disabled с «Проверяем…», вращение и пульсация отключены, затем действие восстанавливается. Дополнительно HTTP 503 сохраняет сам блок и ранее полученные данные.

### 4. Атомарность

Новых проверок с последующей записью во внешнюю систему нет. Существующий handleRefresh использует синхронный isRefreshingRef для исключения одновременных обновлений; новый элемент вызывает тот же обработчик и сохраняет блокировку при resolvingId и отсутствии проекта. Операции скачивания и принятия решений не изменялись. Новых потоковых ресурсов нет.
