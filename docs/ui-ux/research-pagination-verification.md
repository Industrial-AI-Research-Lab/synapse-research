# Пагинация исследований — проверка 16.10.2026

Реализован одобренный вариант «Размер у фильтров». Клиентская пагинация использует отдельный `src/assets/hooks/usePagination.ts`, панель — `app/research/ResearchPagination.tsx` и соседний SCSS module. Зависимости и REST API не менялись.

## Проверка

- `npm run lint` и `npm run build` в `frontend` — успешно.
- `git diff --check` — успешно.
- Механический Impeccable detector для истории, панели и двух стилей вернул `[]`.
- Браузер: headless Microsoft Edge, Playwright, reduced motion. API подменён тестовыми ответами; серверные данные и действующий Synapse не изменялись.
- Реальная функция генерации номеров из хука проверена для каждой страницы при общем количестве от 1 до 1000 страниц: максимум шесть элементов, первая / текущая / последняя присутствуют, числа упорядочены, ключи уникальны.
- Проверены 300 исследований, переключение 5 / 10, начало / середина / конец, отключённые стрелки, нажатие Enter, фильтры обоих типов и состояний, отсутствие совпадений.
- Проверены задержанная первая загрузка на странице 11, обновление вкладки, переход в исследование и возвращение по ссылке с сохранением страницы, размера и фильтров.
- Виртуальные часы браузера подтвердили сохранение страницы при опросе через 30 секунд. Сокращение списка с 300 до 7 записей на последней странице переводит на первую; последующее увеличение списка не возвращает прежнюю страницу.
- Размеры списков 0 / 1 / 5 / 10 / 11, недопустимые параметры адреса, HTTP 401 и 503 проверены отдельно.
- Ширины 1440 / 1024 / 768 / 390 / 320 px: горизонтального переполнения нет, навигация помещается в нижнюю панель, видимые кнопки минимум 44 × 44 px. Визуально просмотрены верх и низ на 1440 и 390 px.
- Ошибок JavaScript в браузере нет.

Сценарий проверки и результаты находятся в игнорируемой `.impeccable/review/`: `research-pagination-check.cjs`, `research-pagination-result.json`, снимки `research-pagination-*.png` и `research-pagination-top-*.png`. Сценарий использует установленный в рабочем окружении Playwright; отдельного тестового пакета в зависимости приложения не добавлено.

### 2. Конкретные предположения о возможной ошибке

1. Hook:50 мог бы ограничить начальную страницу 11 до 1 до прихода ответа. Проверка `items === undefined` сохраняет номер; задержанный запрос подтвердил диапазон 101–110.
2. Hook:57 мог бы оставить скрытый номер 30 после уменьшения списка и восстановить его при росте. Состояние синхронно ограничивается допустимым номером; shrink / expand подтвердил сохранение страницы 1.
3. History:274 и Detail:279 могли бы потерять фильтры при возвращении. Обе ссылки передают одну строку параметров; браузер подтвердил восстановление всех четырёх значений.

### 3. Дополнительный неудобный сценарий

На последней странице 300 исследований список сокращён до 7 записей и затем снова увеличен до 300. Проверены отсутствие пустой страницы, скрытие навигации для одной страницы, корректный диапазон и отсутствие возврата на старую страницу. Это проверяет обновление состава списка независимо от нажатий пользователя.

### 4. Чтение → проверка → запись

| Участок | Условие | Граница согласованности |
|---|---|---|
| Хук: resetKey / count → корректировка state | Страница должна принадлежать текущему фильтру и доступному count | Корректировка собственного React state во время render условна и завершается следующим render до фиксации UI. Возвращаемый срез вычисляется по уже ограниченному page |
| setPage / setPageSize | Переход должен сохранять остальные поля state | Функциональные updater работают с последним состоянием; count берётся из текущего render, при смене входного списка новый render повторно ограничивает страницу |
| historySearch → replaceState | Адрес должен соответствовать показанным параметрам | Effect зависит от готовой строки; URL создаётся заново непосредственно перед записью и сохраняет текущий hash и history.state. Нет асинхронной паузы между чтением и записью |
| historySearch → href карточки → href истории | Фильтры и номер должны пережить полную навигацию | Значения переданы параметрами адреса; история заново проверяет допустимые значения после загрузки |

Новых серверных записей, необратимых побочных действий и потоковых ресурсов в изменении нет. Существующая загрузка истории не менялась.
